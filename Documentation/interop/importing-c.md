# Importing C Libraries

Iris can call any C library without writing wrapper code. The build system uses libclang to parse C headers and turn them into Iris modules that you import normally.

## Importing the C Standard Library

The `C_standard_library` artifact dependency gives you access to some standard C headers:

```json
{
    "dependencies": [
        { "name": "C_standard_library" }
    ]
}
```

Then in your Iris source:

```iris
module Use_printf;

import c.stdio as stdio;

export function run() -> ()
{
    var a = 1;
    stdio.printf("Value: %d, pointer: %p\n"c, a, &a);
}
```

The `"…"c` suffix converts a string literal to `*C_char`, which is what `printf` expects.

## Importing a Custom C Header

Place the C header in your project and add it as a dependency artifact of type `"import_c_header"`:

```json
{
    "name": "Artifact_name",
    "version": "0.1.0",
    "type": "library",
    "sources": [
        {
            "type": "import_c_header",
            "headers": [
                {
                    "name": "c_interface.module_name",
                    "header": "c_interface.h"
                }
            ],
            "public_prefixes": [],
            "remove_prefixes": []
        },
    ]
}
```

Then in any Iris file that depends on `my_c_lib`:

```iris
import c_interface.module_name as my_lib;

export function call_it() -> ()
{
    my_lib.some_c_function();
}
```

## C Type Mapping

When the imported C header uses C types, Iris provides matching built-in types:

| C type | Iris type |
|---|---|
| `char` | `C_char` |
| `short` | `C_short` |
| `int` | `C_int` |
| `long` | `C_long` |
| `long long` | `C_long_long` |
| `unsigned int` | `C_unsigned_int` |
| `bool` / `_Bool` | `C_bool` |
| `void *` | `*mutable Byte` |

## Pointer Members and `Optional`

C spells a nullable pointer and a never-null pointer the same way, as `T*`. By default Iris keeps
that spelling: **a pointer member of an imported struct or union is imported as a plain `*T`**, which
is the direct reading of the C declaration and keeps imported headers usable without changes.

### Turning the wrapping on

Set `wrap_pointers_as_optional` to `true` to import pointer members as
[`Optional::<*T>`](../language/optional-type.md) instead, so the null case has to be handled before
the pointer can be used:

```iris
var node = get_node();

if node.parent.has_value
{
    use(node.parent.value);
}
```

This costs nothing at runtime — `Optional::<*T>` and `*T` are the same bytes — and it changes no
ABI, only what the Iris type system requires of the caller. Pointers that are not struct or union
members (function parameters, return types, globals) are unaffected and stay `*T` either way.

The setting can be applied to a whole `import_c_header` source group, or to a single header, which
wins over the group:

```json
{
    "type": "import_c_header",
    "wrap_pointers_as_optional": true,
    "headers": [
        { "name": "c.mine",  "header": "mine.h" },
        { "name": "c.imgui", "header": "cimgui.h", "wrap_pointers_as_optional": false }
    ]
}
```

The default is `false`. `iris import-c-header` takes the same setting as `--optional-pointers`:

```
iris import-c-header c.mine mine.h out.irisb --optional-pointers
```

### Opting a member out

A header generated by `iris` records which members really were a plain `*T` in Iris, using a
`raw_pointer_members=` field in its `IRIS_META` comment. Those members stay `*T` even when the
wrapping is on:

```c
/** IRIS_META v=1 module=my_module name=Node kind=struct raw_pointer_members=next */
struct my_module_Node {
    struct my_module_Node* parent;   /* no annotation -> Optional::<*Node> */
    struct my_module_Node* next;     /* annotated     -> *Node */
};
```

You can add the same annotation by hand to a third-party header when a pointer member is documented
as never null. It is the finest-grained control, for opting individual members out while the rest of
a header keeps wrapping.
